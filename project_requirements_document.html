Project Requirements

Lets Discuss

Version 2.0 • Comprehensive Specification

1 Project Overview

Lets Discuss is a robust, dynamic discussion platform and blog application. It is designed to facilitate secure and scalable conversations through text and multimedia posts, live comments, and nested replies. The platform is strictly organized across four distinct user tiers and supports private, group-based interactions alongside public forums.

2 Tech Stack

  • Backend: Laravel API
  • Frontend: React SPA
  • Real-time: WebSockets (Reverb/Pusher)

3 User Roles & Permissions

1. Guest

  • Can view all public posts.
  • Can create posts (requires minimum data/captcha).
  • Can comment on public posts (if allowed by author).

2. User

  • Inherits Guest permissions.
  • Can view posts in groups they are explicitly added to.
  • Cannot create groups or restrict visibility.

3. Verified User

  • Inherits User permissions.
  • Can restrict who comments on or sees their posts.
  • Can create groups & publish exclusively to them.

4. Administrator

  • Global Read: Can see all posts (public, private, group).
  • Has all Verified User capabilities.
  • Global moderation and role assignment.

4 Core Features

Post & Comment Creation

  • Accessible to all roles, with varying permissions.
  • Constraint: Posts are limited to Text OR Text + Images (Strict max: 4 images).
  • Restrictions: Verified/Admins can toggle who can view or comment on specific posts.

Live Interactions & Groups

  • Real-time: WebSockets power live comments and replies without page refresh.
  • Groups: Created by Verified/Admins. Users must be explicitly added to see/participate in group posts.
  • Visibility Rule: Standard users see public + their groups. Admins see everything globally.

5 5-Phase Development Plan

Phase 1: Planning & Architecture

Define project scope, user stories, and architecture design.

  • Database schema design (Users, Roles, Posts, Comments, Groups, Media).
  • API contract and endpoint documentation.
  • UI/UX wireframing for the React SPA.

Phase 2: Backend Development (Laravel API)

Build out the core engine, authentication, and endpoints.

  • Implement Sanctum Auth and RBAC (Role-Based Access Control) middleware.
  • CRUD operations for Posts, Comments, and Groups.
  • Media upload logic (enforcing the 4-image limit).
  • WebSocket configuration for live events.

Phase 3: Frontend Development (React SPA)

Develop the user interface with a strict focus on performance.

  • Implement responsive UI using Tailwind CSS.
  • Performance Focus: Emphasize robust state management (e.g., Zustand/Redux) and memoization to minimize unnecessary re-renders on live feed updates.
  • Integrate WebSockets for real-time comment/reply injection.

Phase 4: Testing & QA

Ensure platform stability, security, and performance. (See detailed testing section below).

Phase 5: Deployment & Maintenance

Launch the application and monitor post-deployment metrics.

  • CI/CD pipeline setup via GitHub Actions / GitLab CI.
  • Server provisioning (Nginx, PHP-FPM, Node.js for sockets, DB).
  • Post-launch monitoring and iterative patch deployments.

6 Testing Requirements

Unit & Integration Testing

  • Unit (Backend): Use PHPUnit to test models, authorization policies, and image count validation logic.
  • Unit (Frontend): Use Jest / React Testing Library for isolated component testing (e.g., post renderer, comment form).
  • Integration: Test API endpoints end-to-end and ensure WebSockets correctly broadcast events across active sessions.

End-to-End (E2E) Testing

  • Use Cypress or Playwright to simulate complex user flows.
  • Test critical paths: Guest posting, Admin restricting a post, User attempting to access a group they don't belong to.

Performance Testing

  • Frontend: Utilize React DevTools Profiling to identify and eliminate wasteful component re-renders during high-volume live comment feeds.
  • Backend: DB Query optimization (e.g., Eager loading relationships in Laravel to prevent N+1 query problems).

Security Testing

  • Content Security Policy (CSP): Strict enforcement to prevent unauthorized script execution.
  • XSS Prevention: Rigorous sanitization of all text inputs in posts and comments.
  • RBAC Validation: Automated tests ensuring Users absolutely cannot spoof Admin/Verified roles or bypass group restrictions.
